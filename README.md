## 本地版本管理与审查

当前项目目录为 `/Users/hector/work_space/Codex/apps/muscle`，使用独立本地 Git 仓库管理。迁移后的审查结果与已知问题见 [2026-09-17 审查报告](docs/review-2026-09-17.md)。初始基线包含待修复问题，不代表功能全部验收或已发布。

日常使用 `git status` 查看状态，`git diff` 审查改动，再按明确文件路径执行 `git add` 与 `git commit`。`node_modules`、本机私有配置、凭证和训练导出不纳入版本管理；依赖通过 `npm ci` 恢复。浏览器/微信存储里的实际训练数据不在 Git 中，需要另行导出备份。

后续按“完成修改 → 测试 → 审查明确文件 → 提交 → 推送 origin/main”同步，不监听每次文件保存、不自动上传未完成工作。GitHub 自动运行检查并生成静态发布包，不自动改变域名或发布微信。Cloudflare/国内托管的配置见 [GitHub 与静态托管](docs/github-static-hosting.md)。较早重建记录见 [重建进度](docs/rebuild-progress.md)。

## 查看预览

使用 Node.js 24 LTS 或兼容的更高版本（CI 使用 `.nvmrc` 中的 24），运行 `npm ci` 后再运行 `npm run start:local`，访问终端打印的地址（默认 http://127.0.0.1:4173）。本地服务独立于启动终端运行，端口占用时选择其他空闲端口。`npm run status:local` 查看地址和版本，`npm run restart:local` 更新服务，`npm run stop:local` 停止服务。服务仅监听本机；电脑重启后需再次启动，不是开机自启或生产托管。日志在 `runtime/local-server.log`。前台调试仍可用 `npm run preview`。首次点击右上角登录入口创建管理员；无默认密码。账号数据库默认在 `runtime/`，不进入 Git。直接打开 `preview/index.html` 或仅静态托管时只能使用访客本地存储，不能登录或跨设备同步。

`?qa=名称` 使用独立测试存储，不向用户档案注入演示数据。网页预览和微信小程序的数据相互独立。

## 版本与回声管理

当前版本 **v0.2.6 · 20260922.4**，唯一版本来源是 `miniprogram/lib/release.js`，软件版本与 `package.json` 一致。网页顶部点击版本号可查看构建日期与修改摘要，小程序档案页显示相同版本。修改后递增构建号，避免把浏览器旧页面误认为新版。

管理员登录后通过 **账号 → 回声设置** 配置底部回声及背景留言墙。背景支持纯文字、毛玻璃卡片、关闭；方向可选倾斜交叉、上下交错、水平流动，速度为像素/秒，0 表示暂停。颜色、浓度、角度和模糊可分别调整。预览及恢复默认不写库，保存才全站生效；其他已打开页面最长约 30 秒刷新配置。允许个人样式时，用户可在风格中选择“跟随全站”；全站强制样式不覆盖个人暂停和系统减少动态效果。

v0.2.1 新增动作卡片单独/全部收起，折叠摘要保留重量、组次、计量单位、图解与排序入口；进行中训练显示完成进度。折叠仅改变界面，保留输入和冻结计划。微信计划页同步支持折叠，原生设备尚未验证。表情面板改为行内完整展开，表情按钮不提交留言；玻璃设置增加真实素材对照和背景柔化。

配置存入独立 SQLite 表，管理员权限、来源校验、并发版本检查及审计独立于训练数据。详见 [本地版本与回声设置](docs/release-0.2.0.md)。纯静态部署只能使用内置默认值与本机偏好，无法提供管理 API。

## 训练逻辑边界

本地算法研究准备：管理员导出当前授权研究快照后，可运行 `npm run research:prepare -- 输入.json runtime/research/新版本目录`。包含样本质检、用户与时间隔离和基线评估；不自动训练或替换处方，管理备份不能直接作为研究输入。见 [本地算法研究流程](docs/local-model-preparation.md)。

本项目提供一般健身模板，并非经验证的个体处方。PB 的 2–10 次同时使用 Epley 和 Brzycki 公式，单次直接返回实测重量。使用两公式较低值乘以保守系数作为训练基准，再从目标次数与余力反算工作重量。增肌与力量目标有不同次数和组数配置。完整公式、文献来源、初始试重及产品默认值的区别见 `docs/scientific-basis.md`，界面可点击“计算依据”。

新手、65 岁及以上、长期中断或无近期 PB 使用技术适应模板。疲劳较高时降量；新手疲劳恢复不超过技术日负荷。疼痛阻止计划生成。近期深蹲/硬拉互相检查下肢恢复间隔。未完成主项次数不推进周期，最近一次未完成训练的高 RPE 也参与判断。

跨日草稿不允许继续打组；归档使用用户确认的已发生日期，只保存实际完成组。年龄、体重不直接修改实际 PB，也不推算辅助重量。未知负荷默认待试重，也可选择自行填写实际工作重量（不作为经过验证的推荐）。之后仅用同动作、同器械、相同计量的记录与余力调整。试重独立保存，不计成绩与工作组，但参与恢复判断。具体研究支持原则、产品规则及个体校准参数见 [处方依据](docs/prescription-evidence.md)。

广泛训练原则参考：https://acsm.org/resistance-training-guidelines-update-2026/

## 素材

人体图由 `lib/anatomy.js` 中原创 Canvas 几何生成，为简化肌群示意。器械与动作图片由内置图像工具原创生成，没有复制 MuscleWiki 图像、视频或源码。动作提示为本项目编写，未包含动作教学视频。

原图保留在发布排除目录 `art-originals/`，不进入 Git 或小程序；来源和逐图检查意见在 `docs/media-sources/`。优化图片和详情页放入五个动作分包，网页复用同一素材清单。已提交的优化素材可直接运行，无需重新生成；本机原图可通过 `npm run build:media` 重新打包。`npm run check:release-media` 检查 52 套覆盖率与包体预算，不等于微信编译包体验证。

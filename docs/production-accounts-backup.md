# 正式账号与每周本地备份

## 测试与生产隔离

- 本地测试仍使用 `runtime/big3.sqlite`，原有 demo 账号和记录保留；不要把该数据库复制到正式服务器。
- 设置 `NODE_ENV=production` 或 `BIG3_ORIGIN` 即启用生产保护。正式默认数据库为独立的 `runtime/big3-production.sqlite`，也可使用 `BIG3_DB` 指定持久化路径。
- 生产启动要求 `BIG3_ORIGIN` 是正式 HTTPS 来源。含 demo 账号的数据库会拒绝启动，不自动删除或改写测试数据；测试数据生成脚本也拒绝在生产配置下运行。
- 生产网页不提供“首次访问创建管理员”。`/api/auth/setup` 和 demo 调试接口关闭，现有 demo 登录令牌亦不可用。
- 普通用户自己选择用户名和至少 8 位密码，注册只生成 member 身份；提交 `role=admin` 不能提升权限。没有默认管理员密码。
- 静态产物不包含 server、tests、runtime 或测试口令；本地 HTTP 文件白名单也禁止访问服务器源码、数据库及环境文件。不得公开提交含个人数据的 runtime 或备份文件。

## 管理员初始化

以下为未来部署时的操作说明，本次没有发布站点或更改 DNS。

在服务器终端运行，密码直接输入，不回显，也不要放入命令行参数、代码或截图：

```sh
NODE_ENV=production BIG3_ORIGIN=https://big3.hectorgao.com npm run admin:create
```

数据库路径须与正式进程保持一致；使用 `BIG3_DB` 时，两处都设置为同一路径。初始化已有管理员的数据库会拒绝重复创建，不重置现有账号。

再以相同配置启动服务：

```sh
NODE_ENV=production BIG3_ORIGIN=https://big3.hectorgao.com npm run preview
```

Node 仅监听本机地址，仍需另行配置 HTTPS 反向代理、进程托管和持久化磁盘。正式站点应完成管理员初始化及注册检查后才对外开放。静态网页托管本身不提供账号后端或同步。

## 每周回本地

1. 在正式网站登录自己的管理员账号，进入“账号 → 用户管理”。
2. 点击“下载每周档案备份”，确认敏感资料提示，将生成的 `jugetiezi-users-时间.json` 保存到本机私密备份目录。
3. 确认浏览器下载完成，按时间保留不同副本。页面显示的是上次生成时间，不代表操作系统已成功保存文件。

这是手动、按需生成的全量数据快照，不是自动定时任务，也不是只导出最近七天。各用户按独立 ID 保存用户名、档案、完整训练记录、恢复反馈、收藏、草稿、校准信息和数据版本；排除 demo 账号。

文件为未加密 JSON，含个人资料，不能公开传播或提交 Git。**不包含密码、密码哈希、登录令牌、管理员默认口令，也不是完整服务器数据库备份**。留言、服务器配置、登录状态和审计日志不在该档案文件中。超过 25 MB 时接口拒绝网页导出，需要服务器端数据库备份流程。

下载不会覆盖管理员自己的档案、其他用户记录或本机访客数据。本轮没有实现自动合并/恢复全体账号；管理档案也不能直接当作单用户备份导入。灾难恢复应另行配置并验证服务器数据库备份。

## 与算法研究的区别

管理备份用于数据保管，不代表研究授权。“导出授权研究数据”保持独立，只导出当前明确同意的真实用户；模拟数据不参与研究。备份、下载或新记录同步均不会自动修改其他用户的处方规则。

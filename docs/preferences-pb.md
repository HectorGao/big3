# 动作类型与自动成绩更新

## 动作类型

- 今日训练顶部与档案中的器械选项共用 `profile.equipment`，未设置时兼容为全部允许。
- 自重与杠铃、哑铃、器械、绳索同等参与筛选，不再作为永远允许的例外。
- 修改后清除预览中的手动替换及编辑，使用现有恢复、周负荷、组次规则重算当前与未来两周建议。历史记录不变。
- 已开始训练的目标冻结，顶部筛选锁定；结束或放弃后再改。
- 替代动作取自审查过的关联列表，并受器械、腰背负担、酸痛和重复动作限制。无合适替代时明确省略，不为凑数量加入无关动作。
- 负重臀桥是地面杠铃变式，有独立 ID、计量方式、能力记录及三阶段原创图；不借用自重臀桥或凳上臀推的负荷。
- 核心动作之间、腿弯举与臀桥之间并非完全等效；替换说明保留这一限制，未知负荷仍须试重。

## 自动成绩

- 保存训练与更新档案由 `store.finish` 一次写入完成。失败不清除草稿，也不部分更新档案。
- 只认实际完成、明确成功且动作合格的三大项原动作；排除热身、试重、失败、未完成、变式和不兼容单位。
- 单次超过档案基准时更新 `profile.pb`，保存实际日期、来源记录 ID；这是实际完成的单次最佳，不证明已测试到极限。
- 2–10 次、记录余力为 0–2 的组，保守 e1RM 超过现有基准时更新 `profile.estimatedPB`。原始重量和次数保留，不改写成虚构的单次重量，也不覆盖实测单次 PB。
- Epley/Brzycki 估算沿用已有计算；余力门槛是产品规则而非科学保证。单个多次组的新高不会直接提高训练基准，仍须走近期多次表现校准。
- `record.pbUpdates` 保留本次更新前后的值。仅在本次保存触发，不回填旧记录缺失的成功、质量或余力。
- 修改个人档案仍允许手动纠正；这些记录不是比赛认证成绩。

## 验证边界

自动化覆盖器械组合、真实替换、独立校准、PB/估算区分、部分完成、重复保存和写入失败；网页检查桌面与手机视口的完整保存流程、图示阶段和排版。
小程序页面逻辑通过 Node 模拟调用检查，不等于微信开发者工具或真机验证。新增图为生成素材的初步视觉筛查，未由专业教练实地审定。本次未发布或部署。

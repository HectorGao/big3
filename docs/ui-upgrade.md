# 训练工作台与账号升级

## 交互与数据

- 网页桌面、平板、手机共用页面状态与保存操作。训练中固定显示“查看训练计划”，查看时固定显示“继续当前训练”；原目标只读，实际记录独立。
- 训练设置开始后收起并锁定。按动作分组记录，显式图解、试重、直接填写、放弃/恢复该组；未完成或放弃组不计实际工作量。无完成组结束只写跳过事件。
- 直接填写不是教练验证过的负荷。只填写该动作未完成组，不改变冻结目标，不生成试重或 PB；真正成功完成后才走原有成绩审核。
- 新增/替换使用同一肌群动作库。解剖图标出本日主要肌群，支持名称、图示、动作名与器械筛选。颜色与中文标签同时区分器械。
- 无可靠同动作、同设备记录时保持待定重量。器械名称为空表示常用设备；更换设备需另命名，标重不做跨设备换算。
- 不勾选杠铃后可采用腿举、器械推胸等相关肌群训练；不声称与三大项专项等价，不用这些成绩更新三大项 PB。
- 52 套原创动作图、153 个阶段。新增器械推胸经过助手视觉筛查，未经过专业教练现场审定。

## 疲劳与证据

研究原则与产品规则分开：

1. [Larsen 2021 自我调节系统综述](https://pubmed.ncbi.nlm.nih.gov/33520457/)：14 项研究、356 名健康参与者，支持以实际表现、RPE/RIR 等调节训练的思路；不支持把任意 1–5 分直接当作生理测量。
2. [2024 准备度自我调节范围综述](https://pubmed.ncbi.nlm.nih.gov/38665139/)：准备度指标应用方式多样，主观准备度与具体处方映射的证据有限。没有证据证明本产品的五档阈值适合所有个人。
3. [Haugen 2023 器械与自由重量系统综述](https://pubmed.ncbi.nlm.nih.gov/37582807/)：增肌差异未明确检出；力量提升具有练习与测试方式的特异性。因此允许器械动作，但不将器械成绩转换成杠铃 PB。

当前可校准产品默认值（受更高优先级的疼痛、间隔、酸痛限制约束）：

| 状态 | 常规训练的起点 |
| --- | --- |
| 1 精力较好 | 保持基准处方，不因感觉好而自动冲极限 |
| 2 一般 | 已知重量约留 2.5% 余量，保留组数，次数型动作多留 1 次余力 |
| 3 中等疲劳 | 已知重量约降低 10%，每动作少 1 组、最低 1 组，多留 1 次余力；不静默改成与 4 档相同内容 |
| 4 明显疲劳 | 降为恢复日，主导动作最多 1 组、最多 1 个低负担辅助，至少保留 5 次余力 |
| 5 或疼痛 | 不生成负重处方，可补记已经发生的实际训练 |

重量按器械档位向下取整，1/2 档在小重量处可能同档；这时余力目标仍有区别，不为了数字不同而制造过大的档位跳变。助力动作增加助力代表降低难度。上述比例不是文献验证的个人最佳值，应根据热身和长期实际表现校准；没有可靠能力数据则仍待试重。

## 本地账号服务

需要支持 `node:sqlite` 的 Node.js（本轮使用本机 Node 26.9.0 测试）。`npm ci` 后运行 `npm run preview`，打开打印的本地地址。服务只监听 `127.0.0.1`；本轮不做公网或手机局域网部署。

首次进入右上角“登录 / 注册”，由用户自行创建管理员，无默认密码。之后普通用户注册独立用户名，登录后取得同账号记录。访客原数据不自动上传；需要在账号窗口明确选择“导入此设备访客档案”。

- 数据库默认 `runtime/big3.sqlite`，可用 `BIG3_DB` 指定。运行文件不进入 Git、静态网页资源包或微信包。
- Cookie 会话、随机令牌哈希、带盐 scrypt 密码、来源校验、参数化查询、账号隔离、限流与管理员权限由服务端执行。
- 登录后同步整个训练档案快照，带版本比较。离线保留本机数据；冲突不自动覆盖，用户选择前保留本机冲突备份。不声称可以自动合并两个设备的并发训练。
- 同步约在保存后 600 ms 提交，其他设备前台每 20 秒拉取，也可“立即同步”。关页前仍可能有未提交改动，未同步提示不可忽略。
- 管理员可以查看所有注册用户档案、训练记录及留言，查看与管理操作写入审计表。留言只按纯文本呈现，支持 emoji，作者及管理员可删除留言。
- 研究导出只含自愿授权者的去标识数据；去标识不保证匿名。撤回阻止以后导出，已经下载的副本须人工处理。不会根据某一专业用户的数据自动重写全体处方。
- 本机缓存退出后仍保留，共享设备应使用浏览器访客模式。备份数据库时先停止服务，再复制整个 `runtime` 目录；恢复前保留当前目录副本。没有密码找回、账户删除流程、自动备份或生产监控。

公网发布前仍需独立审查 HTTPS、首管理员初始化、注册策略、数据库备份与恢复、隐私告知、撤回/删除流程及部署资源限制。静态托管仅提供访客离线功能；账号同步必须同时运行后端，不能仅上传静态网页就宣称支持账号同步。

## 验证边界

- 自动化覆盖共享处方、冻结目标、直接填写、放弃组、部分完成、器械专属计划、账号权限、版本冲突、留言与研究授权。
- 浏览器验证桌面与手机的动作选择、图解、输入、保存、账号隔离、多设备同步和冲突副本。测试使用独立浏览器、访客 QA 命名空间及临时数据库，不修改真实档案。
- 微信页面处理器共用处方和保存逻辑，接入直接填写、放弃组、图解入口与冻结计划查看；网页的账号与新版肌群选动作弹窗尚未接入微信端。
- 微信开发者工具、微信真机、原生 Android/iOS、手机实体设备触控、教练实地审定均未验证。本地后端可运行不代表已正式部署。

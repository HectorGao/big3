# 网页部署与域名接入

## 本次发布范围

发布现有网页、共享计算逻辑、50 套动作图。完整项目继续保存在 Git；公开的静态发布包只包含必要资源，不包含原图、测试文件、微信页面源码、私人配置或用户记录。

当前版本仍是本机记录版：没有云端账户、跨设备同步或专家数据收集。每个浏览器自行保存自己的训练资料，不等于有服务端用户隔离。把网址从 localhost 换到线上地址，或从托管域名换到自定义域名，会产生不同的浏览器存储空间。请先在旧地址“我的档案”导出备份，再到新地址恢复；不要清除浏览器数据。

## 可重复发布

1. `npm ci` 恢复依赖，`npm test` 检查共享逻辑与控制器。
2. `npm run build` 生成白名单发布目录 `dist/`；`npm run check:web` 校验引用、文件哈希和素材。
3. `npm run test:web` 在临时本机端口验证真正发布产物，完成后关闭服务。需要安装可用的 Playwright 与 Chrome；本机已有运行环境可通过 NODE_PATH 使用。
4. 提交完整源代码并推送部署站点的私有源码仓库，读取完整 Git HEAD；凭证仅限单次命令，不写入仓库或配置。
5. `npm run package:web` 创建新目录中的归档，不删除旧目录。只打包已校验产物及 `.openai/hosting.json`，不打包源码树。
6. Sites 保存该提交对应版本，再部署该版本。保留同一 `project_id`，更新时不另建站点；以部署服务返回的成功状态和 URL 为准。

构建给脚本和样式添加内容版本参数；发布不清空训练资料。不要在多人使用期间未经确认更改存储键或重置本地数据。

标准 Sites 打包器 `skills/sites-hosting/scripts/package-site.sh` 包含自动递归删除临时目录，`prepare-site-build.cjs` 也会递归删除目标。根据本项目禁止脚本批量删除文件的要求，本项目采用无删除的静态打包适配器，保留 `dist/index.html` 和 `dist/.openai/hosting.json` 的相同归档契约。暂存目录保留在忽略的 `.release-artifacts/`，不上传为网页资源。

## 阿里云 DNS

域名注册在阿里云不要求网站也部署在阿里云。先在托管站点添加用户确认的完整域名，再使用服务实际返回的记录；不能直接猜测 CNAME 或 IP。

- 建议使用独立子域名（例如 `fit.example.com`），避免影响现有网站和邮箱。
- 在阿里云“云解析 DNS → 公网权威解析 → 域名 → 解析设置”添加记录。
- 子域名通常填写主机记录 `fit`、记录类型 `CNAME`，记录值用托管服务返回的 `cname_target`，不要填写 `https://` 或路径。
- 同时添加托管服务返回的所有 TXT / CNAME 验证记录。主机记录要相对于当前 DNS 区域填写，不能重复拼接主域名。
- TTL 可用默认值。根域名 `@` 使用服务返回的根域名 A 记录，不自行查询一个 CDN 临时 IP 填进去。
- 已有同名记录冲突时先核实用途，不能直接删除；不修改无关 MX、NS、TXT 记录。
- 如果域名实际权威 DNS 不在阿里云，记录应添加到当前权威 DNS 服务商。
- 等待 DNS 与 HTTPS 证书都就绪，再验证自定义域名。DNS 指向本身不会改变网站访问权限。

官方操作说明：https://help.aliyun.com/zh/dns/pubz-add-parsing-record

具体记录待用户提供完整域名后，由站点绑定接口返回并记录；未取得真实记录前，不宣称域名已绑定。
